# v1: Build the first version of SeizureWatch

This plan builds the first working version of the app: a phone-friendly website where we log seizures the moment they happen, keep his medication history, record his bloodwork, and keep his background in one place. It goes online first and adds one section at a time, so we can start logging real seizures within the first couple of phases and keep using it while the rest is built.

- **Date:** 2026-11-04.
- **Status:** In progress.
- **Goal:** All four sections from `Roadmap/GlobalRoadmap.md` live at one shared web address, with a seizure loggable from the home screen in one tap.
- **Runtime boundary:** Local development until V1.4; production (Vercel) from then on, deployed only by the operator.
- **Safety boundary:** No record is lost or silently overwritten by an app save. Every save is validated on the server, a double-tap never creates a second record, and a save that conflicts with the other person's edit is refused, not merged. Deletes are deliberate, confirmed actions and are the only way a record is removed. Database-provider failure or account loss is outside the app's control; V1.1 records what backup Neon provides.

## 0. Decisions this plan assumes

Product decisions are in `Roadmap/GlobalRoadmap.md` §Decisions and are cited here as **GR:** followed by the decision's name. The technical decisions below were made by the plan author; the operator signs off by approving this plan.

**Approval gate:** no Phase 1 task starts until the operator has approved V-D1–V-D5. Approving this plan as a whole counts; if the operator changes one decision, every task citing it is re-read before it starts.

### V-D1 — Database and data access

- **Proposed:** Postgres on Neon (free tier, created through Vercel), accessed with Drizzle ORM over the `pg` driver. Schema in `src/lib/db/schema.ts`, migrations generated by `drizzle-kit` into `drizzle/`. Tests run against an in-memory PGlite database with the same migrations applied, so they need no network or account.
- **Evidence:** Vercel's serverless functions can't keep a local database file, so a hosted database is required (GR: online hosting). Drizzle supports both `pg` and PGlite with one schema.
- **Decision and rationale:** Approved by the operator, 2026-11-04.

### V-D2 — Deploys

- **Proposed:** A GitHub repository (`zalee49/seizurewatch`, public by the operator's choice; see V1.1 As built) connected to Vercel, which deploys every push to `main`. Pushing is always the operator's call (global rules), so deploying a phase means the operator pushes, or tells the agent to push.
- **Evidence:** It's Vercel's default flow and needs no CLI on the phones' side.
- **Decision and rationale:** Approved by the operator, 2026-11-04.

### V-D3 — Household time zone

- **Proposed:** All calendar days, "today" and "days since" are computed in one fixed zone, `America/New_York` (this Mac's zone), held in the constant `HOUSEHOLD_TIME_ZONE` in `src/lib/time.ts` (not an environment variable). Instants are stored in UTC (`timestamptz`); calendar-only values (birthday, medication start dates) are stored as `date`.
- **Evidence:** Pages render on the server, which runs in UTC and doesn't know the phone's time zone. One fixed zone keeps both phones and the server in agreement about which day a seizure belongs to.
- **Decision and rationale:** Approved by the operator, 2026-11-04.

### V-D4 — Two people editing the same record

- **Proposed:** Every edit form carries the record's `updatedAt`. If the record changed since the form loaded, the save is refused with "Someone else changed this — reload to see their version", and nothing is written. Adding new records never conflicts.
- **Evidence:** GR: two people, one shared record, no login. Merging edits silently would lose one person's changes.
- **Decision and rationale:** Approved by the operator, 2026-11-04.

### V-D5 — Libraries

- **Proposed:** `zod` for server-side validation, `date-fns` and `@date-fns/tz` for time zone math, `recharts` for bloodwork charts, `vitest` for tests. The calendar is a plain month grid built with Tailwind, not a calendar library.
- **Evidence:** Each covers one need the app has. A month grid of dots is simpler than configuring a calendar library.
- **Decision and rationale:** Approved by the operator, 2026-11-04.

## Phase 2 — Seizure logging and calendar

Largest phase. Payoff: real seizures get logged from day one, with the calendar showing how often they happen.

### V2.1 [boundary] — Save and load seizures and responses

**Parallel:** nothing. **Depends on:** V1.2; V-D3, V-D4; GR: Adding a seizure.

**Reachability:** via V2.2, V2.3.

**Builds:** The app can save a seizure the instant it starts, stop its timer, add details and responses later, and list seizures for any range of days, with every save checked on the server.

**What exists.** From V1.2: tables `seizures` and `seizure_responses` in `src/lib/db/schema.ts`; `Db`, `getDb()` (`src/lib/db/client.ts`); `createTestDb()` (`src/test/db.ts`); `SaveResult<T>` and the conflict message (`src/lib/data/result.ts`); `dayKey`, `parseHouseholdDateTime` (`src/lib/time.ts`).

**Inputs.**

- Seizure start from the "Seizure now" tap: client-generated `id` (UUID) and `startedAt`. Repeated with the same `id`: the existing row is returned, nothing new is written. Malformed UUID or `startedAt` more than 5 minutes in the future: `invalid`.
- Detail and response forms (`FormData`). Missing optional fields: stored as null. Malformed date, number or enum value: `invalid`, with a `fieldErrors` entry naming the field, and nothing written. `endedAt` not after `startedAt`, or a duration over 2 hours: `invalid`. Stale `updatedAt`: `conflict`. Entering a duration on a seizure that hasn't been stopped sets `endedAt = startedAt + duration` and so stops it; leaving duration blank on an unstopped seizure leaves it unstopped.
- Stopping a seizure. A second stop, or stopping one already stopped: success, returning the row with its first `ended_at` unchanged. A stop time over 2 hours after the start: `invalid`, nothing written, and the seizure stays unstopped (it will show "Duration not recorded"). A stop for an unknown `id`: `not_found`.
- Deletes (`deleteSeizure`, `deleteResponse`). Deliberate and confirmed in the UI (V2.3), so they carry no `updatedAt` guard: a delete of an unknown `id` returns `not_found`, and a detail save that arrives after a delete returns `not_found`, never a resurrection.
- Rows read back from the database. An unknown `seizure_type` or `severity` value (from an older schema) is returned as `null`, never thrown, so one bad row can't break a page.

**What to build.**

- [x] `src/lib/data/seizures.ts`, every function taking `db: Db` first:

```ts
type Seizure = { id: string; startedAt: Date; endedAt: Date | null; seizureType: SeizureType | null;
  severity: Severity | null; beforeSymptoms: string | null; afterSymptoms: string | null;
  triggers: string | null; notes: string | null; recoveryMinutes: number | null;
  updatedAt: Date; responses: SeizureResponse[] };
type SeizureResponse = { id: string; kind: 'rescue_med' | 'other'; medicationName: string | null;
  doseAmount: number | null; doseUnit: string | null; givenAt: Date | null; description: string | null };
createSeizure(db, { id, startedAt }): Promise<SaveResult<Seizure>>   // insert ... on conflict (id) do nothing
stopSeizure(db, id, endedAt: Date): Promise<SaveResult<Seizure>>      // only if ended_at is null
updateSeizure(db, id, expectedUpdatedAt: Date, input: SeizureDetailsInput): Promise<SaveResult<Seizure>>
deleteSeizure(db, id): Promise<SaveResult<{ id: string }>>
addResponse(db, seizureId, input: ResponseInput): Promise<SaveResult<SeizureResponse>>
deleteResponse(db, responseId): Promise<SaveResult<{ id: string }>>
getSeizure(db, id): Promise<Seizure | null>
getActiveSeizure(db, now: Date): Promise<Seizure | null>  // ended_at null and started within the last 2 hours
getLastSeizure(db): Promise<Seizure | null>
listSeizuresBetween(db, from: Date, to: Date): Promise<Seizure[]>  // started_at in [from, to), ascending
```

`SeizureDetailsInput` holds every editable field, with `endedAt` or `durationSeconds` (if both are sent, `endedAt` wins). A seizure not stopped within 2 hours is no longer "active" and shows "Duration not recorded"; the app never makes up a duration. `createSeizure` inserts with `on conflict (id) do nothing` and then re-reads by `id`, so a retry returns the row actually stored even if its `startedAt` differs from the retry's. Every read maps stored enum text to the typed union by hand; an unrecognized value maps to `null` (see Inputs), never a throwing parse. Drizzle returns `numeric` columns as strings: every data function converts them to `number` before returning.

**What to build.**

- [x] `src/lib/data/bloodwork.ts`:

```ts
type BloodResult = { id: string; testName: string; value: number; unit: string; rangeLow: number | null; rangeHigh: number | null };
type BloodDraw = { id: string; drawnAt: Date; lab: string | null; notes: string | null; updatedAt: Date; results: BloodResult[] };
type TrendSeries = { key: string; testName: string; unit: string;
  points: { drawId: string; drawnAt: Date; value: number; rangeLow: number | null; rangeHigh: number | null }[] };
createDraw(db, input): Promise<SaveResult<BloodDraw>>      // draw and results in one transaction
updateDraw(db, id, expectedUpdatedAt: Date, input): Promise<SaveResult<BloodDraw>>  // replaces the result rows
deleteDraw(db, id): Promise<SaveResult<{ id: string }>>
listDraws(db): Promise<BloodDraw[]>                        // newest first
getDraw(db, id): Promise<BloodDraw | null>
listTrendSeries(db): Promise<TrendSeries[]>                // key = lower(trim(testName)) + '|' + lower(trim(unit)); only series with 2+ points
```

- [x] Zod schemas in `src/lib/validation/bloodwork.ts`; `src/app/bloodwork/actions.ts` (`"use server"`) with `revalidatePath('/', 'layout')`.

**Boundary checklist.** Create and update are all-or-nothing transactions; a failed result row leaves no half-saved draw. `updateDraw` replaces the result rows inside its transaction (delete, then insert), so result `id`s change on every edit — nothing outside the draw may hold one. The trend key ignores case and spacing but not unit.

**Tests.** New `src/lib/data/bloodwork.test.ts`: a draw saves with its results; one invalid row saves nothing; "Phenobarbital " and "phenobarbital" with the same unit form one series; different units form two; a test seen once makes no series. Run `npx vitest run src/lib/data/bloodwork.test.ts`.
